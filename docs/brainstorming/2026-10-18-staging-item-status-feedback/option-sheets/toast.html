토스트는 잠깐 떴다가 사라지는 작은 알림입니다. 지금 앱은 sonner 라이브러리로 화면 오른쪽 아래에 띄웁니다(providers.tsx). 이 시트에서는 위치, 언제 쓰는지, 여러 개가 한꺼번에 생길 때의 처리, 그리고 지금 있는 20곳의 사용처를 정합니다. 화면 모형은 앱 레이아웃(왼쪽 48px 사이드바, 작업 영역 왼쪽 위의 breadcrumb, 18×9 Grid)을 실제 비율로 그린 것입니다.

질문 1토스트를 어디에 띄울까

토스트가 뜨는 경우는 대부분 Grid 화면입니다(드래그 실패, Bit 상세 저장 실패, SaaS의 저장 실패). breadcrumb은 Grid 화면에만 있고, Inbox·Archive·Trash·Calendar에는 없습니다. breadcrumb의 크기는 그 아래 Grid 칸을 막는 데 쓰이므로(모형의 빨간 점선 칸), 토스트는 breadcrumb 묶음 바깥에 따로 띄워야 합니다. 그래야 막히는 칸 수가 바뀌지 않습니다.

이렇게 확인해 보세요
  1. 아래 버튼에서 A / B / C 위치를 바꿔 가며 토스트 띄우기를 눌러 보세요.
  2. 화면을 Grid → Inbox → Trash로 바꿔서 breadcrumb이 없는 화면에서는 어디에 뜨는지 보세요.
  3. "방금 한 일과 이어져 보이는지", "카드를 가리는 게 거슬리는지"를 보시면 됩니다.
  4. 참고: Grid 화면은 실제 배치·비율(48px 사이드바, breadcrumb 묶음, 18×9 칸)로 그렸고, Inbox·Trash 화면은 영역 배치만 나타낸 단순 모형입니다. 토스트 크기는 sonner 기본 폭(356px)입니다.
위치 화면

A. 작업 영역 왼쪽 위 (Grid에서는 breadcrumb 바로 아래)권장

  • "내가 지금 어디 있나"를 읽는 자리 바로 밑이라, 방금 한 일과 이어져 보입니다. 토스트 메모(2026-04-28)가 처음부터 원하던 방향입니다.
  • 화면 왼쪽 위는 눈이 가장 먼저 가는 곳이라, 실패를 놓치기 어렵습니다.
  • breadcrumb이 없는 화면에서도 같은 왼쪽 위에 뜹니다. 규칙은 "작업 영역 왼쪽 위" 하나입니다.
  • 단점: 그 아래 첫 몇 칸의 카드를 몇 초 가립니다(Inbox에서는 Pool 윗부분). 대신 Inbox는 대부분 아이템 위에 표시하므로 토스트가 거의 뜨지 않습니다.
  • 구현: sonner의 offset을 breadcrumb 묶음의 실제 아래 끝에 맞춥니다. breadcrumb 크기는 이미 측정하고 있습니다.

B. 작업 영역 오른쪽 위

  • 모든 화면에서 같은 자리이고, breadcrumb과 부딪히지 않습니다.
  • 단점: Grid 오른쪽 위 카드를 가리고, 방금 한 일(대개 Grid 가운데나 왼쪽)과 떨어져 보입니다.

C. 오른쪽 아래 (지금 그대로)

  • 변경할 게 없고, 많은 앱이 쓰는 익숙한 자리입니다.
  • 단점: 작업 공간과 떨어져 있어서 놓치기 쉽습니다. 토스트 메모가 바꾸고 싶어 했던 바로 그 점입니다.

질문 2토스트는 언제 쓰나

토스트 메모의 기준과 SaaS S28을 1·2라운드 결정에 맞춰 하나로 합쳤습니다. 핵심은 "결과가 눈앞에 보이면 쓰지 않는다"입니다.

쓴다GridDO 예
① 저장이 실패해서 화면을 되돌렸을 때 (S28)SaaS에서 드래그 이동이 서버에서 실패해 카드가 원래 칸으로 돌아감 → "Couldn't move “Venue”. It's back where it was."
② 막힌 이유가 놓은 자리에서 보이지 않을 때Node 카드에 Bit를 놓았는데 그 Node 안의 Grid가 가득 참, Node를 자기 하위로 옮기려 함
③ 결과가 지금 화면 밖에 있을 때휴지통에서 복원(복원된 Node는 원래 Grid에 있음), 영구 삭제·휴지통 비우기(확인 대화상자가 닫힌 뒤의 결과)
④ 오프라인일 때 저장을 시도했을 때 (S27)"You're offline. Changes can't be saved right now."

질문 3여러 개가 한꺼번에 생길 때, 얼마나 보여 줄 때

SaaS에서는 인터넷이 잠깐 끊기면 저장 실패가 연달아 생길 수 있습니다. 예를 들어 카드 세 개를 빠르게 옮겼는데 셋 다 실패하는 경우입니다(S28: "묶어서 하나로").

묶는 방식

위 Grid 모형에 뜹니다(질문 1에서 고른 위치). 토스트에 마우스를 올리면 시간이 멈춥니다.

A. 같은 종류는 하나로 합치고 개수 표시권장

  • 토스트가 떠 있는 동안 같은 종류가 또 생기면, 새로 띄우지 않고 그 토스트의 문장을 "Couldn't save 3 changes…"로 바꾸고 시간을 다시 잽니다.
  • 다른 종류(예: 저장 실패 + 오프라인)는 따로 뜨고, 최대 3개까지 보입니다.
  • "얼마 동안 묶을지"를 정할 필요 없이, 토스트가 보이는 동안 묶습니다.

B. 쌓기

  • 정보는 다 보이지만, 같은 문장 세 개가 화면을 덮습니다. S28의 "묶어서 하나로"와 맞지 않습니다.

C. 마지막 것만

  • 가장 조용하지만, 몇 개가 실패했는지 알 수 없습니다.
같이 정하려는 기본값 (따로 묻지 않습니다)
  1. 시간: 성공 4초, 실패 6초. 마우스를 올리거나 키보드 포커스가 있거나 다른 탭에 가 있으면 멈춥니다(sonner 기본 동작). 실패 토스트에는 닫기(×) 버튼을 둡니다.
  2. 문장 형식: "무엇이 안 됐나. 지금 화면이 어떤 상태인가." 예: Couldn't move “Venue”. It's back where it was. 문구는 Inbox처럼 한 곳의 copy 모듈에서 관리합니다.
  3. 스크린리더: 성공·실패 모두 polite로 읽습니다(sonner 기본). 실패라고 끼어들어 읽지는 않습니다.
  4. 모양: 지금의 richColors(고정된 빨강·초록 배경)를 빼고, 테마 색(배경·글자·테두리)을 따르게 합니다. 종류는 아이콘 모양(✓ / !)으로 구분합니다. 아래 비교를 테마를 바꿔 가며 보세요. 테마별 마감은 테마 단계에서 합니다.
지금 (richColors)
Unable to update deadline.
Node restored.
바꾼 뒤 (테마 색 + 아이콘 모양)
Couldn't update the deadline. The old date is back.
