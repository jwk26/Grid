SaaS로 바뀌면 생기는 상태들(연결 불안정·오프라인, 첫 로딩, 로딩 실패, 로그인 만료)이 화면 어디에 나타날지 정합니다. 모양(색·아이콘·글꼴)은 SaaS 결정(S27·S40)에 따라 계정 모달과 함께 별도 옵션 시트에서 고르므로, 여기 그린 모양은 임시입니다. 위치만 보세요.

질문 1연결 표시를 어디에 둘까

S27: 평소에는 아무것도 없고, 요청이 실패하면 "불안정"(저장은 됨), 브라우저가 오프라인이거나 세 번 연속 실패하면 "오프라인"(저장 막힘)입니다. 오프라인에서 저장을 시도하면 화면은 그대로이고 토스트가 뜹니다.

이렇게 확인해 보세요
  1. 상태를 불안정, 오프라인으로 바꿔 가며 세 위치를 비교하세요.
  2. 표시 위에 마우스를 올리면 설명이 나옵니다.
  3. 오프라인에서 저장 시도를 누르면 토스트가 경로 자리(왼쪽 위)에 뜹니다. 표시와 토스트가 서로 이어져 보이는지 보세요.
위치
상태

A. 계정 아이콘에 작은 배지권장

  • 모든 화면에 늘 있는 자리이고, 배지라서 사이드바 아이콘들이 밀리지 않습니다.
  • 왼쪽 위(Home·계정)는 눈이 먼저 가는 곳이고, 토스트가 뜨는 경로 자리와도 가깝습니다.
  • 연결은 "내 계정이 서버와 이어져 있나"에 관한 것이라 계정 아이콘과 뜻이 맞습니다.
  • 모양으로 구분합니다: 불안정은 ! 배지, 오프라인은 끊긴 Wi-Fi 배지. 색은 토스트와 같은 노랑·빨강 계열입니다.

B. 사이드바 아래쪽 칸

  • 따로 칸이 있어 잘 보이지만, 생겼다 사라질 때 아래쪽 아이콘들이 움직이고 눈이 덜 갑니다.

C. 작업 영역 오른쪽 위

  • 가장 눈에 띄지만, Grid 위에 떠서 오른쪽 위 카드를 가립니다. 오프라인이 길어지면 계속 가립니다.

질문 2첫 로딩·로딩 실패 화면의 범위

S26: 데이터가 0.3초 안에 오면 아무것도 보이지 않고, 넘으면 로딩 화면이 나옵니다. 실패하면 이유 한 줄과 Retry가 나옵니다(게스트 생성 실패도 같은 화면). 정할 것은 이 화면이 창 전체를 덮느냐, 사이드바는 남기느냐입니다.

A. 창 전체권장

Loading your grid…

Couldn’t load your grid

The server didn’t respond.

Retry
  • 사이드바의 Inbox·Archive 항목과 숫자 배지도 데이터가 있어야 그릴 수 있어서, 반쯤 비어 있는 사이드바가 보이지 않습니다.
  • "아직 준비 안 됨"이 한 장면으로 분명합니다. 빠르면(0.3초 이내) 어차피 보이지 않습니다.

B. 사이드바는 두고 작업 영역만

Loading your grid…

  • 앱 틀이 먼저 보여서 조금 더 빨라 보입니다.
  • 단점: 사이드바 버튼을 눌러도 아직 아무 일도 안 일어나고, Inbox 숫자 배지 같은 것들이 비어 있다가 나중에 채워집니다.

질문 3로그인이 만료되면

S16은 "세션 갱신에 실패하면 게스트 상태로 돌아가고, 계정 모달에서 다시 로그인한다"로 정했습니다. 그런데 게스트가 되는 순간 새 게스트 계정이 만들어지고 데모 데이터가 복사되어(S10·S23), 화면이 남의 Grid처럼 바뀝니다. 사용자는 "내 데이터가 사라졌다"고 느낍니다. 실제로는 드물게 일어나지만(정상적으로는 자동 갱신), 일어나면 가장 놀라운 순간입니다.

A. 막는 화면: "로그인이 만료됐어요"권장

  • 사용자가 "게스트로 계속"을 고르기 전에는 게스트 계정을 만들지 않아서, 쓰레기 게스트 계정도 생기지 않습니다.

C. S16 그대로 (조용히 게스트)

  • 아무 안내 없이 데모 Grid가 보입니다. 데이터를 잃은 것처럼 보입니다.

질문 4Phase 35 MI-14: 새로고침 후에도 마지막으로 고른 Scratch를 기억할까

지금은 새로고침하면 Inbox가 항상 첫 번째 Scratch를 엽니다. 작업하던 Scratch로 돌아가려면 다시 골라야 합니다.

A. 이 기기의 브라우저에 기억권장

  • 이미 Inbox 정렬 설정을 저장하는 곳(triage-preferences-store)에 "마지막 Scratch id"를 하나 더 둡니다.
  • SaaS S11이 "기기별 설정은 브라우저 저장소"로 정한 것과 같은 분류입니다.
  • 그 Scratch가 지워졌거나 다른 계정이면(id가 없음) 지금처럼 첫 Scratch를 엽니다.

B. 서버에 계정별로 기억

  • 다른 기기에서도 이어지지만, 여러 기기 사용은 요구사항이 아니고(S03) 서버에 칸과 쓰기 함수가 하나 더 필요합니다.

C. 지금처럼 첫 Scratch

  • 변경 없음. 불편이 남습니다.

기본값따로 묻지 않고 같이 정하려는 것

  1. 스크린리더: 불안정·오프라인이 되면 한 번 polite로 읽습니다. 복구되면 화면에는 아무것도 띄우지 않지만(S27), 스크린리더에만 "Back online."을 한 번 읽습니다. 그래야 오프라인이라고 들은 사용자가 계속 오프라인으로 믿지 않습니다.
  2. 오프라인 저장 시도 토스트: 노랑 계열, 끊긴 Wi-Fi 아이콘, "You’re offline. Changes can’t be saved right now." 같은 종류는 하나로 묶습니다(3라운드 규칙).
  3. 로딩 화면: 0.3초 뒤에 나타나고(S26), 화면이 바쁘다는 것을 스크린리더에 알립니다. 로딩 실패·만료 화면은 열릴 때 포커스를 첫 버튼으로 옮깁니다.
  4. 배경 새로고침 실패(S26): 화면은 그대로 두고 연결 표시만 "불안정"으로 바꿉니다.
